# Test Plan — E-commerce Website

## 1. Introduction

This test plan describes the testing approach for the SauceDemo e-commerce web application. The purpose is to verify the core application functionalities and identify defects through manual testing.

## 2. Testing Objectives

- Verify that application features work according to expected behavior.
- Validate positive and negative user scenarios.
- Identify defects and document them clearly.
- Verify the shopping and checkout workflow.
- Evaluate the usability and reliability of key features.

## 3. Scope of Testing

### In Scope
- Login and Logout
- Product Listing
- Product Sorting
- Add to Cart
- Shopping Cart
- Checkout Information
- Order Summary
- Order Confirmation

### Out of Scope
- Performance testing
- Security penetration testing
- Payment gateway integration testing
- Automated testing
- Backend database testing

## 4. Testing Approach

Black-box manual testing will be performed.

The following testing techniques will be used:

- Functional Testing
- Positive Testing
- Negative Testing
- Smoke Testing
- Regression Testing
- Boundary Value Analysis
- Equivalence Partitioning
- Exploratory Testing

## 5. Test Environment

- Application: SauceDemo
- URL: https://www.saucedemo.com/
- Browser: Google Chrome
- Operating System: Windows 11
- Testing Type: Manual Testing

## 6. Test Data

Demo credentials will be used for login testing.

Customer information will be entered using fictional test data.

No real personal or payment information will be used.

## 7. Entry Criteria

- The application is accessible.
- Test scenarios have been prepared.
- Test data is available.
- The testing environment is ready.

## 8. Exit Criteria

- Planned test cases have been executed where possible.
- Test results have been documented.
- Reproducible defects have been reported.
- A test summary report has been prepared.

## 9. Deliverables

- Test Plan
- Test Scenarios
- Test Cases
- Test Execution Results
- Bug Reports
- Screenshots
- Test Summary Report

## 10. Risks and Limitations

- The practice application may have intentional defects.
- Some application features may be unavailable or restricted.
- Testing is limited to the accessible demo environment.
- Results may differ across browsers and environments.

## 11. Test Schedule

Testing will be performed as a beginner-level portfolio exercise.

The test cases will be executed manually, and the results will be documented after actual execution.

## 12. Conclusion

This project demonstrates the application of manual testing fundamentals through practical testing of an e-commerce application.
